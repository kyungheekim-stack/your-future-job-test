# AI시대 미래직업테스트 — ver2 프로토타입 인수인계

> 이 문서는 **프론트엔드 작업자에게 넘기는 설계 기준**이다.
> 코드는 동작하는 프로토타입이지 완성품이 아니다. 픽셀 정합보다
> **플로우·상태 구분·연동 지점**을 정확히 옮기는 게 목적이다.
>
> 브랜치: `ver2` · 기준 커밋: `e803c65` · 배포: Vercel 프리뷰(브랜치 자동 배포)

---

## 1. 1차와 무엇이 다른가

| 영역 | 1차 (`main`) | ver2 |
|------|--------------|------|
| 크리스탈볼 | 매끈한 구슬 | 로우폴리 (`CrystalBall_new.png`) |
| 결과 로딩 | 파란 링 + 1줄 문구 | 회색 트랙 + 하늘색 링, 2줄 문구 + 참가자 뱃지 |
| 결과 페이지 | 본인 화면 1종 | **본인/공유 × 비회원/가입 = 4종** |
| 공유 | 링크만 전달 (받는 사람은 결과 못 봄) | 결과를 URL에 실어 전달 |
| 가입 CTA | 그 자리에서 블러 해제 | 실제 register URL로 이동 (환경변수) |

**로직은 손대지 않았다.** 46문항 뱅크 → 적응형 20문항 → 105직업 매칭까지
(`lib/flow.ts` · `lib/scoring.ts` · `lib/matching.ts` · `data/*.json`)는 1차 그대로다.
이 부분은 랜덤 플레이 2만 회 시뮬레이션으로 검증된 코드라 **건드리지 말 것.**

## 2. 화면 플로우

```
[광고 / 웹셀링페이지]  ─┐
                        ├─→  /  ──→  /name  ──→  /intro  ──→  /quiz  ──→  /loading  ──→  /result
[앱 홈 상단 플로팅배너] ─┘      테스트홈    이름입력    시작전로딩   20문항      결과로딩       결과
```

`/intro`와 `/loading`은 자동 전환이다 (각각 2.6초). 유저 입력이 없다.

`/quiz`는 라우트가 하나고 내부에서 문항 인덱스만 증가한다.
뒤로가기·새로고침해도 같은 문항이 나오는 이유는 `planQuiz(answers)`가
답변 배열만 받아 전체 경로를 매번 다시 계산하는 순수 함수이기 때문이다.

## 3. 결과 페이지 — 상태 4종

시안의 카드 4장을 **페이지 4개로 만들지 않았다.** 한 라우트(`/result`)의 상태 조합이다.
문구 하나 고칠 때 4군데를 고치지 않기 위해서다.

| 상태 | 상세 영역 | 카드 밑 링크 | 하단 플로팅 CTA |
|------|-----------|--------------|-----------------|
| 본인 · 비회원 | blur(10px) | テストをもう一度 | `SOCRA Tutorに登録する` + `結果をシェア` |
| 본인 · 가입완료 | 공개 | カードを保存する | `結果をシェア` |
| 공유 · 비회원 | blur(10px) | — | `未来の仕事をチェック` |
| 공유 · 가입완료 | 공개 | — | `未来の仕事をチェック` |

### 판별 기준 (`app/result/ResultClient.tsx`)

```
viewer   = URL에 c 파라미터가 있으면 'shared', 없으면 'owner'
isMember = URL의 m=1  ← 앱 웹뷰가 붙여 준다 (아래 §5 참고)
detailOpen = owner면 isMember / shared면 URL의 d=1
```

**주의:** 공유 페이지의 블러 여부는 *받는 사람*이 아니라 ***보낸 사람***이
가입자였는지로 갈린다. 시안 4종을 그렇게 읽었다.
가입자가 보낸 링크는 상세가 다 보여서, 받은 사람이 "나도 해볼까"가 되는 유인 구조다.
이 해석이 기획 의도와 다르면 `detailOpen` 한 줄만 고치면 된다.

## 4. 공유 링크 스키마

결과는 `sessionStorage`에만 있다. 1차에서는 링크를 그대로 보내서
**받은 사람이 홈으로 튕겼다.** ver2는 결과를 URL에 싣는다.

```
/result?c=12&n=ケイ&d=1
         │    │     └ 1이면 상세 공개
         │    └ 이름 (「ケイの未来の職業はこれです！」 헤드라인)
         └ 직업 번호 (1~105)
```

직업 번호 하나로 카드와 상세를 전부 복원한다 (`lib/share.ts`의 `resultFromCareerNumber`).
상세 화면이 쓰는 값이 `main`과 `subs`뿐이라 점수 재계산이 필요 없다.

**DB도 서버도 필요 없다.** 정적 배포만으로 공유가 성립한다.
집계가 필요해지면 그때 붙이면 되고, 광고 성과는 GA4/AppsFlyer로 본다.

## 5. 연동이 필요한 지점 (아직 비어 있음)

프로토타입에서 **의도적으로 자리만 잡아 둔** 곳들이다. 여기가 작업 대상이다.

### ① 설문 결과 서버 전송
`app/result/ResultClient.tsx`의 `goRegister()` 안에 `TODO` 주석.
플로우도상 「Socra Tutor 가입하기」 탭 → **서버에 설문 결과 전송** → register 이동 순서다.
**엔드포인트 주소와 payload 스펙이 필요하다.**

### ② 가입 여부 판별
지금은 URL의 `?m=1`로만 판별한다. 앱 웹뷰에서 결과를 열 때 붙여 주는 걸 전제했다.
실제로는 쿠키·토큰 등 앱과 합의된 방식으로 교체해야 한다.

### ③ register URL
`lib/links.ts` → `NEXT_PUBLIC_REGISTER_URL` 환경변수.
현재 값: `https://socratutor.ai/onboarding/register/phone?returnUrl=%2Fchat`
**비워 두면 이동하지 않고 그 자리에서 상세를 펼친다** (프리뷰에서 화면 확인용).

### ④ 앱 딥링크 (앱 자동실행)
플로우도의 「공유하기 → 바텀시트 → 앱 버튼 탭 → 앱 자동실행」 구간.
**앱 스킴/유니버설 링크 값이 필요하다.** 현재는 `navigator.share` 표준 공유 시트만 쓴다.

### ⑤ OG 이미지
지금 공유하면 링크가 밋밋하게 뜬다. 카드 이미지가 미리보기로 나오게 하려면
`app/result/opengraph-image.tsx`로 동적 생성을 붙여야 한다. (프로토타입 범위 밖)

### ⑥ 히어로 배경색
시안에 "🔵 상단 히어로 배경 (색 여기서 바꾸기)"로 되어 있다.
AI 유형별로 바꾸는 건지 확인 필요. **현재는 고정색이다.**
바꾼다면 `lib/constants.ts`의 `AI_TYPE_COLOR`를 재사용하면 된다.

## 6. 확인용 URL

프리뷰 주소 뒤에 붙이면 4종을 전부 볼 수 있다.

| 상태 | URL |
|------|-----|
| 공유 · 비회원 | `/result?c=1&n=ケイ` |
| 공유 · 가입완료 | `/result?c=1&n=ケイ&d=1` |
| 본인 · 비회원 | 테스트 완주 후 `/result` |
| 본인 · 가입완료 | 테스트 완주 후 `/result?m=1` |

`c` 값을 1~105로 바꾸면 다른 직업 카드를 볼 수 있다.

## 7. 알아 둘 것

- **카피 톤은 정중체로 통일했다.** 결과 로딩 시안만 반말체(`全部わかったよ`)였는데
  다른 화면이 전부 정중체라 맞췄다. 되돌리려면 `LoadingClient.tsx` 두 줄이다.
- **폰트는 셀프 호스팅이다.** `fonts.googleapis.com`을 `<link>`로 부르면
  결과 카드를 PNG로 캡처할 때 크로스오리진 때문에 `SecurityError`가 난다.
- **카드 저장은 `html-to-image`의 `toPng`**, `skipFonts: true` + 15초 타임아웃 가드.
  일본어 웹폰트를 인라인하면 30MB가 되고 캡처가 멈춘다.
- **루트 `characters/` 폴더를 지웠다.** `public/characters/`와 완전히 중복이었고
  코드에서 참조하지 않았다. 레포가 110MB 가벼워졌다.
- 결과 페이지는 `useSearchParams` 대신 `window.location.search`를 읽는다.
  `useSearchParams`를 쓰면 Suspense 경계가 강제돼 정적 프리렌더가 깨진다.

## 8. 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck  # tsc --noEmit
npm run build
```

Vercel은 이 폴더를 루트로 지정하면 프레임워크를 자동 감지한다.
환경변수는 `.env.example` 참고.
